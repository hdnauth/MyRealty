# 04. 조합 지표 · AI 분석

## 1. 조합 지표 (공공 데이터를 엮어 새로 정의)

모든 지표는 `series`/`series_values`에 파생 시계열로 저장하고, 정의는 `packages/shared/indicators/*.json`에 선언적으로 관리한다.
단위: 가격은 만원, 면적은 ㎡(화면에서 평 병기, 1평 = 3.3058㎡).

| # | 지표 | 산식 | 의미 · 해석 | 데이터 |
|---|---|---|---|---|
| 1 | **월부담지수** (Payment-to-Income) | `원리금상환액(P × LTV, 주담대금리, 30년 원리금균등) ÷ 가구 월소득 × 100` | 가격만이 아니라 금리까지 반영한 "실제 체감 부담". 가격이 그대로여도 금리가 오르면 상승 | 실거래 중위가, ECOS 주담대 금리, KOSIS 소득 |
| 2 | **PIR** (Price-to-Income) | `지역 중위 매매가 ÷ 연 가구소득` | 소득 대비 가격 수준, 과거 평균 대비 괴리율 함께 표시 | 실거래, KOSIS |
| 3 | **실질가격지수** | `명목 가격지수 ÷ CPI × 100` | 물가 효과 제거 후 진짜 상승분 | R-ONE, CPI |
| 4 | **유동성 대비 가격** | `가격지수 ÷ M2 지수` | 돈이 풀린 만큼 올랐는지, 그 이상인지 | R-ONE, ECOS M2 |
| 5 | **전세가율 · 갭** | `전세 중위가 ÷ 매매 중위가`, `매매 − 전세` (단지·평형·동 단위) | 실수요 지지선, 갭 규모 | 실거래 매매·전세 |
| 6 | **깡통전세 위험 점수** (빌라·오피스텔) | `max(보증금 ÷ 추정 매매가, 보증금 ÷ (공시가격 × 보증기관 인정비율))` → 구간화(안전/주의/위험) | 전세 계약 전 위험 점검. 인정비율은 HUG 전세보증 기준(현행 기준 확인 후 설정값으로 관리) | 전월세, AVM, 공시가격 |
| 7 | **거래 회전율** | `월 매매 건수 ÷ 세대수 × 1000` | 유동성·관심도. 가격보다 먼저 움직이는 경향 | 실거래, K-apt/KOSIS |
| 8 | **가격 모멘텀** | 3·6·12개월 수익률, `신고가 거래 비율 = 직전 최고가 이상 거래 수 ÷ 전체 거래 수` | 추세 강도 | 실거래 |
| 9 | **하락 거래 비율** | `직전 동일 평형 거래 대비 하락 거래 수 ÷ 전체` | 조정 신호 | 실거래 |
| 10 | **공급압력지수** | `(향후 24개월 입주예정 + 미분양) ÷ 기존 재고 세대수` | 공급 과잉/부족 | 청약홈 분양(입주 추정), KOSIS 미분양, 재고 |
| 11 | **공시가격 현실화율** | `공시가격 ÷ (실거래 또는 AVM)` | 보유세 부담 변화 예측, 저평가/고평가 단서 | 공시가격, 실거래 |
| 12 | **토지 가격 배율** | `토지 실거래 ㎡당 가격 ÷ 해당 필지 개별공시지가(㎡)` 의 법정동·지목·용도지역별 중위 | 토지·임야의 시세 추정 기준선 | 토지 실거래, 공시지가 |
| 13 | **상대 성과** | `내 부동산 추정가 수익률 − 유사부동산군/시군구 지수 수익률` | 내 부동산이 시장보다 잘하고 있는지 | AVM, R-ONE |
| 14 | **시장 온도계** (0~100) | 아래 합성 방법 | 관심 지역 매수 여건 한눈에 | 위 지표들 |

### 1.1 시장 온도계 합성

```
구성 지표(시군구 단위, 월):
  + 가격 모멘텀(3M)       + 거래 회전율 변화     + 신고가 비율
  + 매매수급지수(R-ONE)   − 월부담지수 수준      − 공급압력지수
  − 미분양 증감

각 지표를 과거 10년 분포 기준 z-score → 부호 방향 맞춤 → 가중 평균
→ 정규분포 CDF로 0~100 변환
구간: 0–20 냉각 · 20–40 약세 · 40–60 중립 · 60–80 강세 · 80–100 과열
```
- 가중치는 초기 동일 가중 → 과거 데이터로 "향후 6개월 가격 변화"와의 상관 기반 백테스트 후 조정.
- 화면에는 점수와 함께 **기여도 분해**(어떤 요인이 올렸고 내렸는지)를 막대로 보여준다.

### 1.2 커스텀 지표 빌더 (P2)
- 시계열 코드를 변수로 선택 → 수식(사칙연산, `ma(x, n)`, `yoy(x)`, `z(x)`, `lag(x, n)`) 입력 → 서버에서 안전한 파서로 계산(임의 코드 실행 금지).
- 예: `z(yoy(reb.apt_idx.11710)) - z(ecos.mortgage_rate)` → "가격 상승세 대비 금리 부담".

### 1.3 구현 메모 (Phase 3)
- 외부 가격지수 없이도 동작하도록 **실거래로 자체 가격지수**를 만든다: 거래 평당가를 해당 단지의 전 기간 중위 평당가로 나눈 비율의 월 중위(3개월 평활) → 단지 구성 변화 보정.
- 코드: `services/etl/src/myrealty_etl/analytics/indicators.py` (지표 코드표 docstring 참고). 외부 통계 코드는 `series_catalog.py` 에서 관리.
- 가구소득은 KOSIS 연동 전까지 기본값(가계금융복지조사 2023년 가구 평균 경상소득 7,185만원, `INCOME_ANNUAL_MANWON`)을 사용.

### 1.4 생활편의 점수 (추가)
| 항목 | 가중 | 구성 |
|---|---|---|
| 교통 | 25 | 최근접 지하철역(300m 이하 100점 → 1.5km 0점) 70% + 500m 내 버스정류장(10곳 포화) 30% |
| 학교 | 15 | 최근접 초등학교(300m → 1.2km) 60% + 1km 내 중·고교(4곳 포화) 40% |

## 2. 유사 부동산(comps) 알고리즘

1. **후보 필터**: 동일 유형, 반경 R(아파트 2km / 빌라 1km / 토지 법정동+인접동), 최근 24개월 거래 존재, 면적 ±20%, 연식 ±7년.
2. **유사도 점수**: 정규화된 특징 간 가중 거리
   `score = 1 − Σ wᵢ·|xᵢ − yᵢ| / rangeᵢ` (거리, 전용면적, 연식, 세대수, 층, 역까지 거리; 토지는 지목·용도지역·도로접면·면적)
3. **시점 보정**: 비교 거래가를 시군구 가격지수로 현재 시점 환산 `adj = price × idx(now)/idx(deal_date)`
4. 상위 N개를 지도·표로 보여주고, ㎡당 가격 분포에서 내 부동산의 백분위 표시.

## 3. 추정 시세(AVM)

| 유형 | 방법 | 신뢰도 |
|---|---|---|
| 아파트·오피스텔 | ① 동일 단지·동일 평형 최근 거래를 지수로 시점 보정한 가중 중위(최근일수록 가중) ② 거래가 적으면 유사 단지 comps로 보완 ③ 층·향 보정은 단지 내 거래로 추정 | 높음 |
| 연립/다세대 | 헤도닉 모델(LightGBM): 면적, 연식, 층, 대지지분(가능 시), 좌표, 역거리, 공시가격 → ㎡당 가격 | 중간 |
| 단독/다가구 | 헤도닉 + 공시가격 × 지역 배율 | 낮음~중간 |
| 토지·임야 | 개별공시지가 × 지역(법정동·지목·용도지역) 가격 배율 중위, 인근 동일 지목 거래로 범위 제시 | 낮음 |

- 결과는 **점추정 + 구간(10~90 분위)** 과 근거 comps를 함께 저장. 구간이 넓으면 UI에서 "참고 수준"으로 표시.
- 백테스트: 실제 거래 발생 시 직전 추정치와의 오차(MAPE)를 기록해 모델 품질 대시보드로 관리.

## 4. 뉴스 · 정책 · 이벤트 매칭

```
수집(키워드별 네이버 뉴스) → URL/제목 유사도로 중복 제거
  → 1차 필터: 키워드·지역명 규칙 (명백히 무관한 동명이인 지명 제거)
  → 2차: Claude 구조화 출력으로 관련도·카테고리·영향·요약
  → article_links 저장 → relevance ≥ 0.7 이면 알림 후보
정책/규제: 발표 문서에서 대상 지역(법정동/시군구) 목록 추출 → 내 부동산 lawd_cd와 교차
이벤트: events.geom 과 watch_items.geom 의 ST_DWithin(반경) 또는 region_cd 일치
```

## 5. AI 기능 설계 (Claude API)

### 5.1 모델 선택
| 용도 | 모델 | 설정 |
|---|---|---|
| Q&A 에이전트, 부동산 분석, 주간/월간 리포트 | `claude-opus-5` | adaptive thinking, 스트리밍 |
| 대량 뉴스 분류·요약 | 기본 `claude-opus-5` (Batch API) — 비용을 더 줄이려면 `claude-haiku-4-5`로 전환 선택 가능 | 낮은 effort, 구조화 출력 |

- 모델 ID는 설정값(env)으로 관리해 교체 용이하게.
- 거절(`stop_reason: "refusal"`)·`max_tokens` 등 종료 사유를 항상 확인하고 처리.

### 5.2 뉴스 분류 — 구조화 출력 + Batch API
- 하루 3회 신규 기사를 모아 **Message Batches API**로 비동기 처리(실시간 불필요, 비용 절감).
- `output_config.format`(JSON Schema)로 응답 형식을 강제:
  ```json
  {
    "relevance": 0.0,               // 해당 부동산/지역과의 관련도 0~1
    "category": "재건축|교통|규제|대출|공급|학군|개발|시장동향|기타",
    "impact": 0,                    // -2(강한 악재) ~ +2(강한 호재)
    "affected_regions": ["법정동명"],
    "summary": "한 문장 요약"
  }
  ```
- 시스템 프롬프트(분류 기준·예시)와 부동산 컨텍스트를 앞쪽에 고정해 **프롬프트 캐싱** 적중률을 높임. 가변 요소(기사 본문)는 뒤에 배치.

### 5.3 대화형 Q&A — 도구 사용(tool use)
- 모델에게 **임의 SQL을 주지 않고**, 검증된 읽기 전용 도구만 노출 (RLS가 적용된 사용자 세션으로 실행):

| 도구 | 설명 |
|---|---|
| `list_watch_items()` | 내 부동산 목록·요약 |
| `get_item_detail(item_id)` | 속성·추정가·공시가격·지표 |
| `query_transactions(filter)` | 단지/반경/유형/기간 거래 조회(행 수 상한) |
| `find_similar(item_id, n)` | comps |
| `get_series(codes, from, to)` | 거시·지역·조합 지표 시계열 |
| `search_news(item_id \| region, since)` | 연결된 기사·요약 |
| `list_events(region, from, to)` | 청약·정책·이벤트 |
| `simulate_payment(price, ltv, rate, years)` | 결정적 계산기 |

- SDK의 Tool Runner로 루프 처리, `strict: true`로 도구 인자 스키마 보장, 응답은 스트리밍으로 모바일에 점진 표시.
- 답변 규칙(시스템 프롬프트): 수치는 반드시 도구 결과에서 인용, 출처(데이터명·기준일) 표기, 데이터 부족 시 "모름"이라고 답함, 투자 권유 금지.
- UI: 답변 속 도구 결과를 표/차트 카드로 렌더(모델이 만든 숫자가 아니라 도구 결과를 그대로 시각화).

### 5.4 정기 리포트
- **주간 브리핑**(월요일): 지난주 내 부동산별 거래·추정가 변화, 관련 뉴스 Top 3, 이벤트, 온도계 변화 → 5~8줄 요약 + 부동산별 카드. 홈 카드 + 이메일.
- **월간 리포트**: 포트폴리오 순자산 추이, 상대 성과, 리스크(만기·금리 민감도), 다음 달 일정.
- 입력은 ETL이 미리 계산한 JSON 스냅샷 → 모델은 해석·서술만 담당(재현성·비용 통제).

### 5.5 부동산 분석 카드 · 비교 코멘트
- 입력: 속성·지표·comps·뉴스 요약 → 출력(구조화): `strengths[]`, `risks[]`, `checklist[]`, `one_liner`.
- 유형별 체크 포인트 주입: 빌라(깡통전세·위반건축물·대지지분), 토지(도로 접면·용도지역·개발제한), 재건축(연식·용적률·사업 단계).

### 5.6 비용 · 품질 관리
- 요청별 `usage` 저장 → 월 사용량 대시보드, 월 예산 상한 초과 시 배치 작업 보류.
- 뉴스 분류 정답셋(수작업 라벨 100건) 으로 관련도 판단 정확도 주기 점검.
