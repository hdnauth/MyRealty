# 07. 공개 가입 · 기기 기억 · 관리자 기능

요청: ① "로그인 코드 받기" 클릭 시 *This page couldn't load / A server error occurred* 오류 수정 ② 허용 목록 없이 누구나 가입
③ 기기 기억 시 다음 접속 자동 로그인 ④ 환경 설정에 관리자 이메일, 관리자 전용 관리 화면(사용자 관리 등 사이트 전반).

## 1. 로그인 오류 — 원인과 수정

**증상 재현**: 기존 코드로 운영 빌드(`next build && next start`)를 띄우고 DB 에 연결할 수 없는 상태에서 이메일 입력 → "로그인 코드 받기"를 누르면
정확히 같은 화면(`This page couldn't load` · `A server error occurred. Reload to try again.`)이 나온다. 이 화면은 Next.js 가 서버 액션에서
**처리되지 않은 예외**가 발생했을 때 보여주는 기본 전역 오류 화면이다. 로그인 화면 자체는 DB 를 쓰지 않아 정상으로 열리고, 첫 DB 접근이 코드 요청이라 이 시점에 드러난다.

| 원인 | 설명 | 수정 |
|---|---|---|
| 루트 `.env` 미로딩 | `next.config.ts` 의 `loadEnvConfig(루트)` 는 Next 가 먼저 `apps/web` 기준으로 호출한 결과를 캐시해 **무시**된다. 운영 모드에서 `DATABASE_URL`·`AUTH_SECRET`·`SMTP_*` 가 비어 기본값(localhost DB)으로 접속 → 연결 실패 | 루트 `.env.local`·`.env` 를 직접 읽어 비어 있는 변수만 채움(플랫폼 값 우선) |
| 예외 미처리 | DB 연결·스키마 누락·SMTP 오류가 그대로 던져져 전역 오류 화면 | 로그인 액션에서 잡아 원인별 한국어 문구 + 오류 번호 표시, 서버 로그에 같은 번호(`src/lib/errors.ts`) |
| 풀러 호환 | Supabase·Neon 트랜잭션 풀러(6543)에서 prepared statement 오류 가능 | 풀러 주소를 감지하면 자동으로 `prepare: false`, 연결 타임아웃 10초 |
| 메일 무한 대기 | 서버리스에서 SMTP 연결이 멈추면 요청 시간 초과 | nodemailer 연결·응답 타임아웃, 발송 실패 코드는 삭제해 바로 재시도 가능 |
| 원인 파악 어려움 | — | 공개 점검 엔드포인트 `/api/health`(DB·미적용 마이그레이션·AUTH_SECRET·SMTP 여부, 비밀값 없음), `error.tsx`·`global-error.tsx` 한국어 화면 |

배포 후 `/api/health` 가 `{"ok":true}` 가 아니면 응답의 `db`·`dbError`·`pendingMigrations`·`authSecret` 으로 원인을 바로 알 수 있다.

## 2. 구현 계획과 결과

### 2.1 데이터 모델 — `db/migrations/0004_admin.sql`
- `users`: `role`(user|admin), `status`(active|blocked), `admin_note`, `blocked_at`
- `sessions`: `remember`, `last_seen_at`, `ip`
- `ai_usage.user_id`(사용자별 AI 사용량·한도)
- `site_settings`(key/jsonb): `signupMode`, `aiUserMonthlyLimitUsd`, `notice`
- `admin_audit_log`: 관리자 작업 기록

### 2.2 가입 · 로그인 정책 (`src/lib/auth/policy.ts`, 순수 함수 + 단위 테스트)
| 대상 | 판단 |
|---|---|
| 정지된 계정 | 거부(코드 미발송, 응답은 동일) |
| 기존 사용자 | 가입 방식과 무관하게 허용 |
| `ADMIN_EMAILS` | 항상 허용 |
| 신규 | 가입 방식: **누구나(기본)** / 허용 목록만(`allowed_emails` + `ALLOWED_EMAILS`) / 가입 중지 |

코드 확인 시점에 한 번 더 판단해 발송 후 정지·정책 변경도 반영한다. 공개 가입에 맞춰 IP 당 시간당 30회 제한을 추가했다.

### 2.3 이 기기 기억하기
- 로그인 화면 체크박스(기본 켜짐). 켜면 90일 영구 쿠키, 끄면 세션 쿠키(브라우저 종료 시 삭제) + 서버 세션 12시간
- 계속 쓰는 기기는 `proxy.ts` 가 하루 한 번 쿠키를 재발급하고, 페이지 접근 시 DB 세션 만료도 90일로 연장 → 사실상 계속 자동 로그인
- 이미 로그인된 기기로 `/login` 에 오면 바로 원래 화면으로 이동
- 설정 → 로그인된 기기에서 "기억됨/일회성"·최근 접속 확인, 기기별 로그아웃

### 2.4 관리자
- `ADMIN_EMAILS`(쉼표 구분) 또는 관리 화면에서 지정한 `users.role='admin'`
- 환경 변수 관리자와 자기 자신은 화면에서 정지·강등·삭제 불가(잠김 방지)
- 사이드바 "관리", 모바일은 **전체** 탭 → 관리. 관리자가 아니면 `/admin` 은 404

### 2.5 관리 화면 (`/admin`)
| 탭 | 기능 |
|---|---|
| 개요 | 가입 사용자(기기 게스트 수 따로)·신규 가입(7/30일, 게스트 제외)·활성(오늘/7일) 사용자, 세션·로그인 수, 부동산·알림·리포트, 이번 달 AI 비용/예산, 30일 일별 가입, 최근 가입, 설정 문제 경고 |
| 사용자 | 이메일·이름 검색, 가입 사용자/기기 게스트/전체·상태·역할 필터, 부동산 수·기기 수·월 AI 비용·가입일·최근 접속, 페이지 이동 |
| 사용자 상세 | 이용 정지/해제(정지 시 전 기기 로그아웃), 관리자 지정/해제, 모든 기기 로그아웃, 기기별 로그아웃(IP·최근 접속), 표시 이름·관리자 메모, 부동산 목록, 용도별 AI 사용, 계정 삭제(이메일 재입력 확인) |
| 사이트 설정 | 가입 방식, 1인당 월 AI 한도(USD), 전 화면 공지 배너, 허용 목록 일괄 추가·삭제(가입 여부 표시) |
| 시스템 | DB 연결·마이그레이션 상태, 환경 변수·외부 API 설정 여부, 용도별·사용자별 AI 사용량, ETL 최근 실행, 오늘 API 호출, 오래된 코드·만료 세션 정리 |
| 작업 기록 | 모든 관리자 작업(누가·무엇을·대상·세부) 최근 200건 |

### 2.6 다중 사용자 보완
- AI: 전체 예산(`AI_MONTHLY_BUDGET_USD`) + 사용자별 월 한도, 사용량을 사용자별로 기록
- 개발사업(정비구역·철도)은 전 사용자 공용 데이터라 등록·삭제를 관리자 전용으로 변경
- ETL: 정지 사용자는 금리 변경 알림·푸시·다이제스트·정기 리포트에서 제외
- 설정 화면: 사이트 운영 정보(ETL·API 키·허용 목록)는 관리 화면으로 이동, 개인 AI 사용량·회원 탈퇴 추가

## 4. 운영 체크리스트
1. `.env`(또는 배포 환경 변수)에 `ADMIN_EMAILS=내이메일` 추가, `ALLOWED_EMAILS` 는 비워도 됨
2. `cd services/etl && uv run myrealty migrate` (0004 적용)
3. 웹 재시작/재배포 → `/api/health` 확인 → 관리자 이메일로 로그인 → 관리
4. 공개 운영 시 SMTP 필수(없으면 코드가 서버 로그로만 출력), AI 사용 시 관리 → 사이트 설정에서 1인당 한도 권장
