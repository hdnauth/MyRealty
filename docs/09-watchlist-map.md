# 09. 등록 직후 채우기 · 관심 부동산 ↔ 지도 · 지도 표현 설계

> 요청: ① 관심 부동산을 등록해도 대부분 "다음 수집 때"라 쓸모가 적다 → 실시간(백그라운드)으로 불러오기 검토,
> ② 관심 부동산과 지도가 따로 논다 → 연결 계획, ③ 구현한 기능·공공데이터·조합 지표를 지도에 어떻게 보여 줄지,
> ④ 등록 때 채울 수 있는 정보(실거래·호실)와 등록 화면 지도, ⑤ 면적은 실제 있는 평형·호의 면적만,
> ⑥ 주변 거래는 비슷한 것 위주, ⑦ 재개발·재건축 물건에 보여 줄 정보, ⑧ 토지·임야 주변 정보와 넓은 반경.
>
> 이 문서는 무엇을 구현했고(✅) 무엇을 다음에 할지(⬜) 정리한다.

## 1. 요약

| 문제 | 원인 | 이번 변경 |
|---|---|---|
| 등록 직후 빈 항목이 "다음 수집 때" | 수집이 매일 05:50 시군구 단위 배치뿐 | ✅ 그 부동산만 바로 수집(개별 수집) + 단계별 진행 표시, 끝난 항목부터 화면 갱신 |
| 수집 전 단지는 등록 화면에 가격이 없음 | 실거래는 DB 에만 있고, 수집 전이면 비어 있음 | ✅ 등록 화면에서 실거래 API 를 바로 조회(저장 전 미리보기) |
| 없는 면적을 입력할 수 있음 | 평형 '직접 입력'이 항상 열려 있음 | ✅ 대장에 호 목록이 있으면 대장 평형·호에서만 고르고 서버에서도 검증 |
| 지도 ↔ 관심 부동산 단절 | 핀이 상세로 이동만 하고, 상세에는 지도가 없음 | ✅ 지도에 내 부동산 목록·선택 카드, 상세에 "지도" 버튼·"주변 한눈에" 지도, 등록 화면 미니 지도 |
| 주변 거래가 내 부동산과 동떨어짐 | 반경 안 같은 유형 전체 | ✅ 면적 ±20%(토지 ±40%)·준공 ±10년·같은 지목만 기본, "전체 보기" 전환 |
| 정비사업 물건 정보 부족 | 주변 구역 목록만 | ✅ 재개발·재건축 카드(소속 구역·단계 안내·대지지분·신축/분양권 비교) |
| 토지·임야 비교 거래가 거의 없음 | 반경 2km·기간 6개월 | ✅ 기본 반경 토지 5km·임야 10km, 기간 3년, 주변 토지 시장 카드 |

## 2. 등록 직후 바로 채우기 ✅

### 2.1 방법 검토

| 방법 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 웹(Vercel 함수)에서 직접 수집 | 추가 인프라 없음, 가장 빠름 | 실거래 해석·단지 매칭·AVM·입지 점수를 TypeScript 로 다시 만들어야 해 ETL 과 어긋날 위험(중복 거래 해시 등), 함수 시간 제한 | 등록 화면 **미리보기**에만 사용(저장 안 함) |
| **GitHub Actions `workflow_dispatch`** | 매일 수집과 같은 Python 코드·같은 키(Secrets) 그대로, 무료 한도 안 | 러너 기동 30~60초 | **채택** — 저장·계산은 여기서 |
| 별도 워커 서버(큐) | 가장 빠른 기동 | 서버 운영·비용 | 사용자가 늘면 재검토 |
| DB 큐 + 주기 폴링(cron) | 단순 | GitHub cron 최소 5분·지연 큼 | 보류 |

### 2.2 흐름

```
등록(서버 액션) ──▶ item_collect_runs(queued) ──after()──▶ GitHub API: etl-item.yml 실행
                                                              │
상세 화면(DataStatusLive) ◀── 4초마다 /api/items/:id/collect ◀──┤ myrealty item --item <id> --run <run>
   · 단계가 끝날 때마다 router.refresh() → 서버 컴포넌트가 새 데이터로 다시 그림
   · 핵심 데이터(실거래·추정 시세)가 비어 있고 12시간 안에 요청한 적 없으면 화면을 열 때 자동 요청
```

단계: `trades`(최근 12개월, 이 유형만) → `attrs`(대장·토지·공시가격) → `location`(주변 시설·입지 점수) → `valuation`(추정 시세)
→ `news`(뉴스+소량 분류) → `history`(13~36개월, 지수·추정 시세 재계산). 설정은 [06 문서](06-operations.md#개별-수집-등록-직후-바로-채우기).

### 2.3 화면 상태 (상세 › 개요 상단 카드)

| 상태 | 항목 표시 |
|---|---|
| 수집 중 | 진행 막대(n/6) · 해당 항목 "불러오는 중…"(스피너) |
| 끝났는데 데이터 있음 | ✔ + 요약(예: "실거래 132건 연결됨 · 보기") |
| 끝났는데 없음 | 사유: "이 단지와 연결된 거래가 없습니다(신축·거래 없음·단지명 불일치)", "동·호를 입력하면 호별 공동주택가격을 찾습니다" 등 |
| 건너뜀·실패 | "DATA_GO_KR_KEY 미설정", "오늘 호출 한도 초과", "불러오지 못함" + **다시 불러오기** |
| 실행기 미설정 | 기존 안내(매일 아침 수집) |

### 2.4 등록 화면에서 채울 수 있는 정보 (확인 결과)

| 항목 | 원천 | 등록 화면 | 비고 |
|---|---|---|---|
| 유형 판별 | 수집 단지 → 건축물대장 용도 → 토지특성 지목 → 도로명주소 | ✅ 기존 | |
| 평형 목록(세대수) | 건축물대장 전유부 | ✅ 기존 | 대표 면적을 **대장 값**으로(실거래 신고 면적과 소수점 차이 제거) |
| 동·호 → 층·면적 | 건축물대장 전유부 | ✅ 기존 | 호를 고르면 그 호의 전용면적으로 맞춤 |
| 평형별 최근 1년 매매가 | 수집 DB, **없으면 실거래 API 바로 조회** | ✅ 신규 | 수집 전 단지도 평형 카드에 가격 표시 |
| 최근 거래·매매/전세 중위·전세가율 | 같음 | ✅ 신규 | 고른 평형 기준, 안 고르면 전체 |
| 위치·탐색 반경·주변 단지 시세·지하철·학교 | 지오코딩 + 수집 DB | ✅ 신규(미니 지도) | 위치가 맞는지 확인하는 용도가 큼 |
| 토지 지목·면적, 단독 연면적·대지 | 토지특성·건축물대장 | ✅ 기존 | |
| 단독·토지·상가 주변 시세 | 같은 읍면동·비슷한 면적(±40%)·같은 지목 | ✅ 신규 | ㎡당 중위·최근 거래 |
| 공시가격·용도지역·입지 점수·추정 시세 | 여러 API·계산 | 등록 후 개별 수집 | 등록 화면을 느리게 만들지 않도록 |

### 2.5 면적 규칙 ✅
- 대장에 호 목록이 있으면 평형 카드에서만 고른다('직접 입력' 숨김). 호를 고르면 그 호의 전용면적·층을 쓴다.
- 서버(`checkUnitArea`)도 같은 규칙으로 검증: 동·호가 대장에 있으면 그 면적으로 덮어쓰고, 호 없이 면적만 오면 대장 면적 ±0.5㎡ 안이어야 한다(대장 값으로 맞춤). 대장을 못 불러오면(키 없음·API 오류) 막지 않는다.
- 수정 화면에도 같은 검증을 적용.

## 3. 관심 부동산 ↔ 지도

### 3.1 구현 ✅
- **지도 화면**: 옆 목록에 `주변 거래 | 내 부동산` 탭. 내 부동산을 누르거나 핀을 누르면 선택 카드(추정 시세·최근 매매·반경, 상세/비슷한 주변 거래/입지 바로가기, 같은 평형 최근 거래)가 뜨고, 그 부동산 유형의 거래로 필터가 바뀌며 탐색 반경을 그린다.
- 핀에 추정 시세(없으면 최근 매매)를 함께 표시, 내 단지의 가격 라벨은 ★·파란 테두리로 강조.
- **상세 화면**: 제목 옆 "지도" 버튼(`/map?item=`), 개요 탭 "주변 한눈에" 미니 지도(반경·주변 매매 라벨·지하철·학교).
- **등록 화면**: 주소를 고르면 미니 지도로 위치·반경·주변 시세를 먼저 보여 준다.

### 3.2 다음 단계 ⬜
1. 지도에서 단지를 고르고 **"관심 등록"** → 등록 화면에 단지·주소가 채워진 채로 열기(지도 → 관심 부동산 방향).
2. 그룹별 핀 색(보유·매수 후보·관심·전월세), 읽지 않은 알림 뱃지, 비교 목록 번호 핀.
3. ✅ **후보 탐색 필터**: 가격대·평형·준공·전세가율·입지 점수 조건에 맞는 단지만 표시 → [10 문서](10-multi-ai-and-map-search.md#2-지도-조건-검색-)
4. 내 부동산 사이 거리·통근 시간(대중교통 API는 유료가 많아 직선거리부터).

## 4. 무엇을 지도에 어떻게 보여 줄까

### 4.1 원칙
- **줌에 따라 집계 단위를 바꾼다**: 줌 ≤10 시군구, 11~14 읍면동, 15+ 단지·필지. 한 화면 라벨 수를 100개 안쪽으로.
- **색은 한 번에 하나의 지표**(단계 구분 색, 범례 필수), **점·선·면 레이어는 여러 개**를 겹친다. 내 부동산 핀은 항상 맨 위.
- 값이 없는 곳은 회색(0 과 구분). 해석 문구를 범례 옆에 한 줄로("빨강 = 1년 상승 큰 곳").
- 모바일은 아래 목록이 지도와 같은 데이터를 보여 줘 지도 없이도 읽을 수 있게.

| 기능 | 지도에서 |
|---|---|
| 알림 | 알림 있는 부동산 핀 뱃지, 신규 거래 위치 강조(알림에서 지도로 열기) |
| 비교 | 비교 목록 번호 핀, 지도에서 "비교 담기" |
| 포트폴리오 | 보유 자산 핀 크기=평가액, 색=평가 손익 |
| 청약·캘린더 | 기간 슬라이더로 청약·입주 마커 필터 |
| AI | "이 영역 설명해 줘" — 현재 화면 범위·레이어를 도구 입력으로 전달 |
| 리포트 | 주간 리포트에 "내 부동산 주변 변화" 지도 스냅샷 |
| 커스텀 지표 | 사용자 지표를 시군구 색으로 |

### 4.5 기술 설계
- **레이어 레지스트리**(화면): `{key, label, kind: point|label|polygon|line|choropleth, minZoom, legend, fetch}` 한 곳에 정의 → 칩·범례·요청을 자동으로.
- **API**: `/api/map/layers/[key]?bbox&zoom` 이 가벼운 GeoJSON(좌표 소수 5자리)으로 응답. 무거운 집계는 ETL 이 매일 머티리얼라이즈드 뷰(`map_complex_stats`, `map_region_stats`)로 미리 만든다.
- **경계**: 법정동·시군구 경계(공공 SHP)를 PostGIS `region_bounds` 로 적재, 줌별 단순화(`ST_SimplifyPreserveTopology`) 버전 보관.
- **엔진 어댑터**: `addPolygon`·`addPolyline`·`addHeatmap` 추가(네이버·Leaflet 둘 다).
- **성능**: bbox·줌·필터 키로 응답 캐시(`Cache-Control: private, max-age=300`), 라벨 100개 제한, 클러스터링.
