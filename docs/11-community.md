# 11. 동네 이야기(커뮤니티)

아파트 단지·시군구별 게시판. 관심 부동산을 등록하면 그 단지·시군구가 **자동 구독**되어 따로 가입하거나 게시판을 찾을 필요가 없다.
닉네임(앱 전체 공통)으로 활동하고 이메일은 공개되지 않는다.

## 1. 설계 원칙

| 문제 | 대응 |
|---|---|
| 빈 게시판(사용자 대비 단지가 너무 많음) | 단지 글에도 항상 `sgg_cd` 를 저장 → 시군구 게시판에 함께 모임. 단지 화면은 단지 글이 3개 미만이면 같은 시군구 인기글을 섞는다. 신고가·청약을 **데이터 시스템 글**로 올려 대화 소재로 쓰고, 질문에는 **AI 첫 답변** |
| 1인 운영 모더레이션 | 저장 전 규칙 점검(개인정보 마스킹·담합·광고·욕설) → 저장 후 AI 검토(서버 키) → 신고 누적 자동 가림 → 관리 화면 처리 대기 목록 |
| 법적 의무 | 공인중개사법 제33조 제2항(집값 담합) 탐지·보류, 정보통신망법 제44조의2 취지의 신고 누적 임시조치, 운영 원칙 동의 필수 |
| 서버리스(Vercel) | 실시간 채팅 대신 비동기 게시판. 즉시성이 필요한 댓글 알림만 웹에서 바로 푸시 |

## 2. 화면

| 위치 | 내용 |
|---|---|
| `/community` | 내 구독 전체 피드 · 시군구(`?sgg=`) · 단지(`?complex=`) 게시판, 말머리·최신/인기·검색, 구독 버튼, 주간 요약/단지 FAQ |
| `/community/new` | 게시판·말머리·제목·본문, **데이터 첨부**(단지 시세 카드·실거래·지표), 사진(브라우저에서 1280px JPEG 로 축소, 4장), 투표(가격 전망/직접) |
| `/community/posts/[id]` | 본문·첨부 카드·투표, 좋아요·신고·**차단**, 댓글·대댓글(1단계), AI 답변 신고, 관리자 공개/가리기 |
| `/community/profile` | 닉네임(30일에 한 번 변경)·운영 원칙 동의·보유 배지 공개·댓글 푸시, 활동 점수, 거주 인증, 내 글, 차단한 사용자(해제) |
| `/community/rules` | 운영 원칙 |
| 홈 | "내 동네 소식"(구독 게시판 새 글) |
| 단지 상세 · 관심 부동산 "이야기" 탭 | 단지 이야기 미리보기 + 시군구 인기글. 거래 내역의 💬 → 그 거래를 첨부한 글쓰기 |
| 지도 | 가격 라벨에 최근 7일 새 글 수 배지, 선택 카드에 "이야기 N" |
| 지표(요약) | **커뮤니티 심리**: 가격 전망 투표(오른다 +100 / 비슷하다 0 / 내린다 -100) 월 평균, 10표 미만은 대표성 낮음 표시 |
| 관리 › 커뮤니티 | 처리 대기(신고·보류·자동 가림), 공개/가리기/신고 기각/작성 제한 7·30일, 제한 사용자 해제, **AI 답변 신고**(앱 전체 AI 출력). 모든 처리는 작업 기록에 남는다 |
| 관리 › 사이트 설정 | 글쓰기 허용, AI 자동 검토, AI 첫 답변, 자동 가림 신고 수 |

## 3. 데이터 모델(0012_community.sql)

- `users` + `nickname`(lower 고유), `community_agreed_at`, `community_muted_until`, `community_points`
- `community_posts` — `sgg_cd`(필수) + `complex_id`(선택), `category`(question·info·opinion·review·life·data), `kind`(user·system), `attachments` jsonb, `status`(visible·held·hidden·deleted), `moderation` jsonb(flags·ai·by·auto_hidden), 반응 수 캐시, `source_key`(시스템 글 멱등)
- `community_comments`(parent_id 1단계, kind user·ai), `community_reactions`, `community_reports`(대상·신고자 고유)
- `community_polls`(kind custom·outlook) / `community_poll_votes`
- `community_follows` — 관심 부동산 외 직접 구독(자동 구독은 `watch_items` 에서 계산)
- `community_images` — bytea(소규모 전제). 글에 붙지 않은 사진은 하루 뒤 ETL 이 삭제
- `community_residences` — 거주 인증(좌표는 저장하지 않고 단지까지 거리만)
- `community_summaries` — 단지 FAQ·시군구 주간 요약 캐시(12시간)

## 4. 모더레이션 흐름

```
작성 → screenText(규칙)
        ├ 개인정보(전화·이메일·동호수·계좌·주민번호) → 가리고 저장
        └ 담합·광고·욕설 → held(작성자·운영자만 보임)
     → after(): AI 검토(COMMUNITY_AI_MODEL, 서버 키·예산 안에서)
        ├ block  → hidden
        ├ review → held
        └ ok     → 규칙 보류였으면 visible 로 풀어 줌
     → 신고 N건(기본 3) → hidden + 관리자 알림
     → 관리자 처리(moderation.by 기록) 뒤에는 AI·신고가 상태를 바꾸지 않음
```

작성 제한: 가입 24시간 안 글 3·댓글 20, 이후 글 20·댓글 200(하루), 글 30초·댓글 5초 간격, 신고 하루 30건, 사진 하루 20장.
활동 점수: 글 +3, 댓글 +1, 받은 좋아요 +1, 운영자에게 가려지면 -10 → 새내기 / 이웃(20) / 단골(100) / 터줏대감(300).

## 5. 배지

- **거주 인증**: 단지 좌표 반경 250m 안에서 서로 다른 날 3번(30일 안) 위치 확인 → 1년 유지. 위치 정확도 500m 초과는 거부
- **보유**: 본인이 보유로 등록한 단지(지역) + 프로필에서 공개를 켠 경우만(기본 꺼짐)
- **관심**: 관심 부동산으로 등록한 단지(지역)

## 6. AI

| 기능 | 키·비용 | 끄는 법 |
|---|---|---|
| 자동 검토 | 서버 키(`ANTHROPIC_API_KEY`), `COMMUNITY_AI_MODEL`(기본 claude-haiku-4-5), 서버 월 예산 | 관리 › 사이트 설정 |
| 질문 첫 답변 | 서버 키, `ANTHROPIC_MODEL`(effort low), 단지·시군구 데이터만 근거 | 관리 › 사이트 설정 |
| 단지 FAQ · 주간 요약 | 버튼을 누른 사용자의 AI 설정(본인 키 또는 서버 키 + 개인 한도) | — |
| 주간/월간 리포트 | 스냅샷에 `community`(지역 인기글)·`community_sentiment` 추가, "## 동네 이야기" 절 | — |

서버 키가 없거나 예산을 넘으면 AI 단계는 건너뛰고 규칙 점검·신고만 동작한다.

## 7. ETL(`myrealty community`, daily 의 alerts 앞 단계)

1. 시스템 글: 최근 2일 수집된 신고가 매매(같은 평형 ±3㎡, 직전 거래 3건 이상, 하루 단지·평형당 최고 1건) → 단지 게시판, 청약 공고 → 시군구 게시판
2. 인기글 알림: 구독 게시판의 지난 하루 글 중 좋아요×2 + 댓글×3 ≥ 5, 사용자당 하루 1건(`community_hot`, 다이제스트)
3. 고아 사진 정리

## 8. 배포

1. 마이그레이션: GitHub Actions → **Migrate**(또는 `uv run myrealty migrate`)로 `0012_community.sql` 적용. `pg_trgm` 확장이 필요(Supabase 기본 제공)
2. (선택) `COMMUNITY_AI_MODEL` 설정
3. 관리 › 사이트 설정에서 커뮤니티 옵션 확인

## 9. 한계·다음 단계

- 사진은 DB(bytea)에 둔다. 사용자가 늘면 오브젝트 스토리지(Supabase Storage·R2)로 옮긴다(`/api/community/images` 만 바꾸면 됨)
- 검색은 `ilike` + trigram 인덱스. 형태소 검색이 필요해지면 별도 검색 엔진
- 거주 인증은 위치 기반이라 실제 거주를 보증하지 않는다(운영 원칙에 명시)

## 차단(앱 마켓 UGC 정책)

차단은 `community_blocks(user_id, blocked_id)` 한 줄. 차단한 사용자의 글은 목록 쿼리(`listPosts`)에서 빠지고, 글 상세는 본문 대신 "차단한 사용자의 글"과 해제 버튼,
댓글은 "차단한 사용자의 댓글"로 가려진다(대댓글 구조 유지). 그 사용자가 내 글·댓글에 답해도 알림이 가지 않는다. 상대에게는 알리지 않으며 1인당 500명까지.
