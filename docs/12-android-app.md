# 12. Android 앱 · Google Play 등록

웹앱(PWA)을 **Trusted Web Activity(TWA)** 로 감싸 Android 앱으로 낸다. 앱은 크롬 엔진으로 웹을 주소창 없이 전체 화면에 띄우는 껍데기이고,
화면·기능은 모두 웹에 있다. **웹을 배포하면 앱에도 바로 반영**되므로 앱은 아이콘·도메인·패키지·버전이 바뀔 때만 새로 올린다.

> 처음 등록한다면 단계별 안내 [13. Google Play 등록 따라 하기](13-play-store-guide.md)부터 본다. 이 문서는 구성·근거·답변 표 참고용이다.

| 구성 | 위치 |
|---|---|
| Android 프로젝트(Gradle, androidbrowserhelper) | `apps/android/` — [README](../apps/android/README.md) |
| 도메인 인증(Digital Asset Links) | 웹 `/.well-known/assetlinks.json` ← 환경 변수 `ANDROID_PACKAGE_NAME`, `ANDROID_CERT_SHA256` |
| 공개 법적 고지(로그인 없이 열림) | `/legal/privacy`(개인정보처리방침) · `/legal/terms`(이용약관) · `/legal/account-deletion`(계정 삭제) |
| 심사용 로그인 | `REVIEW_LOGIN_EMAIL` + `REVIEW_LOGIN_CODE`(메일 없이 고정 코드) |
| 빌드·서명·업로드 | GitHub Actions **Android**(`.github/workflows/android.yml`) |

## 1. 왜 TWA 인가

- 코드베이스 하나: 화면 31개·서버 액션 54개를 앱용으로 다시 만들지 않는다. 웹과 앱이 항상 같은 버전이다.
- 로그인·웹푸시·오프라인 캐시·위치(거주 인증)·사진 첨부가 크롬의 기능 그대로 동작한다. 웹푸시는 **알림 위임**으로 앱 이름·아이콘으로 표시된다.
- 크롬(또는 TWA 를 지원하는 브라우저, 삼성 인터넷 등)이 없거나 도메인 인증이 실패하면 주소창이 보이는 Custom Tab 으로 열린다.
- 네이티브 전환이 필요해지면 같은 패키지명으로 업데이트하면 되므로 스토어 등록·리뷰는 이어진다.

## 2. 스토어 심사 대응으로 웹에 추가한 것

| Play 정책 | 대응 |
|---|---|
| 개인정보처리방침 공개 URL | `/legal/privacy` — 처리 항목·목적, 보유 기간, 위탁·국외 이전(Vercel·Supabase·GitHub·Anthropic·SMTP), 권리 행사, 보호책임자. 값은 `src/lib/legal.ts` 와 `OPERATOR_NAME`·`SUPPORT_EMAIL` |
| 계정 삭제(앱 안 + 앱 밖 URL) | 앱: 설정 › 회원 탈퇴(기존). 앱 밖: `/legal/account-deletion`(메일 요청 안내, 삭제·보존 데이터 명시) |
| 보관 기간 준수 | 매일 ETL `cleanup` 단계: 로그인 코드 기록·끝난 세션 30일, 처리된 AI 신고 1년 뒤 삭제 |
| 사용자 생성 콘텐츠(UGC) | 기존 운영 원칙 동의·신고·자동 가림·관리 처리 + **사용자 차단**(글은 목록에서 빠지고 댓글은 가려지며 댓글 알림도 오지 않음, 커뮤니티 › 내 활동에서 해제) |
| AI 생성 콘텐츠 | 질문하기 답변·리포트·분석 카드·AI 비교·동네 이야기 요약/AI 답변에 **AI 답변 신고** → 관리 › 커뮤니티 "AI 답변 신고" |
| 심사자 로그인 | 이메일 OTP 는 심사자가 메일을 받을 수 없어 `REVIEW_LOGIN_*` 로 전용 계정만 고정 코드. 관리자 이메일에는 동작하지 않는다 |
| 약관 동의 고지 | 로그인 화면 하단 "계속하면 이용약관·개인정보처리방침에 동의" + 설정 하단 링크 |

DB 변경: `db/migrations/0013_app_store.sql`(`community_blocks`, `ai_feedback`). 배포 전에 `uv run myrealty migrate`(또는 Actions **Migrate**).

## 3. 출시 절차

### 3-1. 준비(한 번)

1. **웹 배포 도메인 확정.** 앱에 들어가는 도메인이다(`apps/android/gradle.properties` 의 `twa.host`, 기본 `myrealty.vercel.app`).
   나중에 바꾸면 앱 업데이트가 필요하니 자체 도메인을 쓸 계획이면 지금 정한다.
2. **패키지명 확정.** 기본 `com.yarch.myrealty`. Play 에 처음 올린 뒤에는 바꿀 수 없다. 바꾸면 `gradle.properties`(`twa.applicationId`), 워크플로(`packageName`), 웹 `ANDROID_PACKAGE_NAME` 을 함께 고친다.
3. **Google Play 개발자 계정** 만들기(play.google.com/console, 등록비 US$25, 신원 확인). 개인 계정은 이름·국가가 스토어에 표시된다.
   > 2023-11 이후 만든 **개인 계정은 프로덕션 출시 전에 비공개 테스트를 테스터 12명 이상, 14일 연속**으로 진행해야 한다. 지인 12명의 Gmail 을 미리 모아 둔다.
4. **업로드 키 만들기**: `apps/android/scripts/create-upload-key.sh`(JDK 필요: `brew install openjdk@21`). 키 파일은 리포 밖(`~/.android-keys/`)에 두고 백업한다.
5. **GitHub Secrets**: `ANDROID_KEYSTORE_BASE64`(키 파일 base64), `ANDROID_KEYSTORE_PASSWORD`.
6. **웹(Vercel) 환경 변수** 후 재배포:
   - `OPERATOR_NAME`(Play 개발자 이름과 같게), `SUPPORT_EMAIL`(Play 연락처 이메일과 같게)
   - `ANDROID_CERT_SHA256` = 업로드 키 SHA-256 (아래 3-3 에서 Play 앱 서명 키를 추가)
   - `REVIEW_LOGIN_EMAIL`(예: `play-review@<내 도메인>` — 관리자 아님), `REVIEW_LOGIN_CODE`(6자리 숫자)
   - 가입 방식이 "허용 목록"이면 심사 이메일을 허용 목록에 넣는다
7. 심사용 계정으로 한 번 로그인해 **관심 부동산 2~3개를 등록**해 둔다(빈 화면이면 "기능 부족"으로 거절될 수 있다). 수집이 끝났는지 확인.

### 3-2. 첫 빌드와 기기 확인

1. GitHub › Actions › **Android** › Run workflow(track 은 무시됨 — 서비스 계정이 아직 없음) → 아티팩트 `myrealty-<번호>.aab` 다운로드.
2. 기기 확인은 디버그 APK 로 한다: `cd apps/android && ./gradlew assembleDebug` → `adb install app/build/outputs/apk/debug/app-debug.apk`.
   디버그 키 지문(`keytool -list -v -keystore ~/.android/debug.keystore -storepass android`)을 `ANDROID_CERT_SHA256` 에 잠시 더하면 주소창 없이 열린다.
   확인할 것: 주소창 없음 · 로그인 유지 · 알림 권한 요청 → 웹푸시가 마이리얼티 이름으로 옴 · 지도 · 사진 첨부 · 거주 인증 위치 권한 · 뒤로 가기 · 다크 모드 스플래시.

### 3-3. Play Console

1. **앱 만들기**: 이름 `마이리얼티`, 기본 언어 한국어, 앱, 무료.
2. **테스트 › 비공개 테스트**(개인 계정 필수) 트랙에 첫 `.aab` 를 **직접 업로드**. 이때 **Play 앱 서명**에 동의한다.
3. **설정 › 앱 무결성 › 앱 서명**에서 **앱 서명 키 인증서 SHA-256** 을 복사해 `ANDROID_CERT_SHA256` 에 쉼표로 추가 → 웹 재배포.
   (Play 에서 받은 앱은 이 키로 서명되므로, 빠뜨리면 설치한 앱에 주소창이 보인다.) `https://<도메인>/.well-known/assetlinks.json` 에 지문 두 개가 보이면 된다.
4. **앱 콘텐츠**(아래 4의 답 사용): 개인정보처리방침, 앱 액세스(심사 계정), 광고(없음), 콘텐츠 등급, 타겟층, 데이터 보안, 금융 기능, 정부 앱 아님, 뉴스 앱 아님.
5. **스토어 등록정보**(아래 5): 설명, 아이콘 512, 그래픽 이미지 1024×500, 휴대전화 스크린샷 2~8장.
6. 테스터 12명 이상을 추가하고 옵트인 링크를 보내 **14일** 유지 → **프로덕션 액세스 신청** → 프로덕션 출시(심사 보통 수일).

### 3-4. 이후 업데이트

- 화면·기능 변경: **웹만 배포**. 앱 업데이트 불필요.
- 앱 변경(아이콘·도메인·targetSdk): `twa.versionName` 올리고 Actions **Android** 실행. 버전 코드는 실행 번호로 자동 증가.
- 자동 업로드: Play Console › 설정 › API 액세스에서 서비스 계정을 만들고(권한: 출시 관리) JSON 을 `PLAY_SERVICE_ACCOUNT_JSON` 시크릿에 넣으면
  워크플로가 선택한 트랙(`internal`/`alpha`/`production`)에 **초안**으로 올린다. Console 에서 검토 후 출시.
- **targetSdk**: Play 는 매년 8월 말 기준 최신 −1 API 를 요구한다(현재 36). 매년 여름 `compileSdk`/`targetSdk` 를 올려 다시 빌드한다.

## 6. 확인이 필요한 것(법·정책)

- **위치정보**: 거주 인증은 기기 위치를 받아 거리만 계산하고 좌표는 저장하지 않는다. 그래도 개인위치정보를 이용한 서비스로 보아
  「위치정보의 보호 및 이용 등에 관한 법률」의 위치기반서비스사업 신고 대상인지 확인한다(방송통신위원회). 신고 전에 출시해야 하면 거주 인증을 끄는 설정을 먼저 추가한다.
- **앱 이름 '마이리얼티'(KIPRIS 조회 2026-10-03)**: '마이리얼티'·'MyRealty'와 같은 상표는 없다. 가장 가까운 것은 여행 서비스 '마이리얼트립(MyRealTrip)' 계열 등록 상표(여행 앱·광고업 포함)로,
  분야와 뒷말이 달라 혼동 가능성은 낮다. 부동산 분야의 '마이리얼셀(MY REALSELL)'은 포기된 출원이다. 다만 '리얼티(realty)'가 부동산을 뜻하는 말이라
  부동산 정보 서비스(36류)·앱(9류)에 상표 출원하면 식별력 부족으로 거절될 수 있다('리얼티원', '엑스 리얼티' 등 거절 사례). 이름으로 쓰는 데는 문제가 없지만
  독점권까지 원하면 로고와 결합해 출원하는 방안을 변리사와 상담한다.
- **처리 위탁 표**(`src/lib/legal.ts`): 실제 쓰는 메일 발송 서비스, DB 지역(Supabase 프로젝트 지역)으로 고친다. 업체를 바꾸면 방침 시행일도 바꾼다.
- **원스토어·갤럭시 스토어**: 같은 `.aab`(원스토어는 `.apk` 도 가능)로 올릴 수 있다. TWA 는 크롬이 없으면 Custom Tab 으로 열리니 기기 확인 후 등록한다.
