# 13. Google Play 등록 따라 하기 (처음 하는 사람용)

위에서부터 순서대로 하면 된다. 각 단계는 **할 일**과 **확인**으로 되어 있다.
앱의 구조·심사 답변 표·스토어 문구는 [12. Android 앱](12-android-app.md)에 있고, 여기서는 그 문서의 표를 가져다 쓴다.

**전체 흐름**

```
웹 배포 → 개발자 계정 → 키 만들기 → 비밀값 넣기 → 앱 파일 만들기
→ Play 에 앱 만들기 → 내부 테스트(내 폰) → 비공개 테스트(12명 × 14일) → 정식 출시
```

**걸리는 시간**: 계정 확인 1~3일, 비공개 테스트 최소 14일, 심사 각 1~7일 → **약 3~4주**. 실제 작업 시간은 3~4시간.

**미리 준비할 것**

- 안드로이드 폰 1대(계정 인증·앱 확인용)
- 해외 결제 가능한 카드(등록비 US$25, 한 번만)
- 신분증(계정 신원 확인)
- **테스터 12명의 Gmail 주소**(가족·지인. 14일 동안 앱을 설치해 두기만 하면 된다)

---

## 1단계. 웹 배포

이 앱은 웹을 띄우는 앱이라 웹이 먼저 준비돼 있어야 한다.

**할 일**
1. `main` 을 GitHub 에 push 한다. Vercel 이 웹을 배포하고 GitHub Actions **DB migrate** 가 새 테이블을 만든다.
2. 실제 웹 주소를 확인한다. `myrealty.vercel.app` 이 아니면 `apps/android/gradle.properties` 의 `twa.host` 를 그 주소로 바꾼다(`https://` 없이).

**확인**: 휴대폰 브라우저에서 아래 세 주소가 **로그인 없이** 열린다.
- `https://<웹 주소>/legal/privacy`
- `https://<웹 주소>/legal/terms`
- `https://<웹 주소>/legal/account-deletion`

## 2단계. Google Play 개발자 계정 만들기

**할 일**
1. <https://play.google.com/console> 에 앱 운영에 쓸 Google 계정으로 들어간다.
2. 계정 유형은 **개인**을 고른다(조직은 사업자 D-U-N-S 번호가 필요).
3. 개발자 이름(스토어에 표시됨, 예: `yarch`), 연락처 이메일·전화번호를 넣고 US$25를 결제한다.
4. 신분증으로 신원 확인을 한다. 안드로이드 기기 인증을 요구하면 폰에 **Play Console 앱**을 설치해 같은 계정으로 로그인한다.

**확인**: Play Console 첫 화면에서 **앱 만들기** 버튼이 눌린다(확인에 1~3일 걸릴 수 있다).

## 3단계. 업로드 키 만들기 (앱 파일 서명용 열쇠)

Play 에 올리는 앱 파일은 내 키로 서명해야 한다. 한 번만 만든다.

**할 일** (이 Mac 터미널에서)
```bash
brew install openjdk@21
cd ~/work/MyRealty
apps/android/scripts/create-upload-key.sh
```
비밀번호를 정해 두 번 입력하면 끝에 값 세 개가 출력된다. 메모해 둔다.
- `[1]` 업로드 키 지문(`AB:CD:…` 형태) → 5단계에서 사용
- `[2]` `~/.android-keys/myrealty-upload.base64.txt` 파일 → 4단계에서 사용
- 정한 비밀번호 → 4단계에서 사용

**꼭 할 것**: `~/.android-keys/myrealty-upload.jks` 파일과 비밀번호를 비밀번호 관리자나 안전한 곳에 백업한다.

## 4단계. GitHub 에 비밀값 넣기

GitHub Actions 가 앱 파일을 만들 때 3단계의 키를 쓴다.

**할 일**: GitHub 리포 → **Settings → Secrets and variables → Actions → New repository secret** 으로 두 개를 만든다.

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `~/.android-keys/myrealty-upload.base64.txt` 내용 전체(VS Code 로 열어 복사) |
| `ANDROID_KEYSTORE_PASSWORD` | 3단계에서 정한 비밀번호 |

등록한 뒤 `myrealty-upload.base64.txt` 는 지운다(`.jks` 원본은 지우지 않는다).

## 5단계. Vercel 에 환경 변수 넣기

**할 일**: Vercel → 프로젝트 → **Settings → Environment Variables** 에 추가한 뒤 **Redeploy** 한다.

| 이름 | 값 | 용도 |
|---|---|---|
| `OPERATOR_NAME` | 2단계 개발자 이름과 같게 | 개인정보처리방침의 운영자 |
| `SUPPORT_EMAIL` | 2단계 연락처 이메일과 같게 | 문의·계정 삭제 요청 주소 |
| `ANDROID_CERT_SHA256` | 3단계 `[1]` 지문 | 앱 주소창 숨김(도메인 인증) |
| `REVIEW_LOGIN_EMAIL` | 예: `play-review@myrealty.invalid` (관리자 아닌 주소. 메일이 안 가므로 없는 주소여도 된다) | Google 심사자 로그인 |
| `REVIEW_LOGIN_CODE` | 아무 6자리 숫자, 예: `482913` | 심사자 로그인 코드 |
| `MAIL_FROM` | `마이리얼티 <보내는 주소>` | 메일 보낸 사람 이름 |

그다음 웹에서 **심사용 이메일로 로그인**(코드 받기 → 위 6자리 입력)해 **관심 부동산을 2~3개 등록**해 둔다. 심사자가 빈 화면만 보면 거절될 수 있다.

**확인**
- `https://<웹 주소>/.well-known/assetlinks.json` 에 `com.yarch.myrealty` 와 지문이 보인다.
- `/legal/privacy` 맨 아래에 운영자 이름과 이메일이 보인다.

## 6단계. 앱 파일(.aab) 만들기

**할 일**
1. GitHub 리포 → **Actions → Android → Run workflow** → 초록 버튼.
2. 5분쯤 뒤 실행이 끝나면 실행 화면 맨 아래 **Artifacts** 에서 `myrealty-<번호>.aab` 를 내려받는다.
3. zip 을 풀면 `app-release.aab` 가 나온다. 이것이 Play 에 올리는 파일이다.

**확인**: 실행이 초록 체크로 끝났다. 빨간색이면 대부분 4단계 비밀값 오타다.

## 7단계. Play Console 에 앱 만들기

**할 일**
1. **앱 만들기** → 앱 이름 `마이리얼티`, 기본 언어 `한국어`, `앱`, `무료` → 선언 체크 → 만들기.
2. 대시보드의 **앱 설정** 할 일 목록을 위에서부터 채운다. 답은 [12. Android 앱 §4](12-android-app.md#4-앱-콘텐츠-답변초안)의 표를 그대로 옮긴다.
   - 개인정보처리방침: `https://<웹 주소>/legal/privacy`
   - 앱 액세스: "일부 기능 제한" → 로그인 없이 쓸 수 있는 범위와, 글쓰기·AI 를 위한 5단계 심사용 이메일·코드·가입 경로(상단 '간편 가입')를 적는다
   - 광고: 없음 · 타겟층: 18세 이상 · 콘텐츠 등급: 설문 작성(사용자 간 소통 "예")
   - 데이터 보안: §4 의 수집 항목 표대로, 공유 없음, 삭제 URL `https://<웹 주소>/legal/account-deletion`
   - 금융 기능·정부 앱·뉴스 앱: 모두 해당 없음
3. **스토어 등록정보**: 문구는 [§5](12-android-app.md#5-스토어-등록정보초안)를 복사한다.
   - 앱 아이콘: `apps/android/store/icon-512.png`
   - 그래픽 이미지: `apps/android/store/feature-graphic.png`
   - 휴대전화 스크린샷 2장 이상: 8단계에서 폰에 설치한 뒤 찍어서 올린다(그 전까지는 비워 둬도 된다)

## 8단계. 내부 테스트 — 내 폰에 먼저 설치

**할 일**
1. **테스트 및 출시 → 테스트 → 내부 테스트 → 테스터** 탭: 이메일 목록을 만들어 **내 Gmail** 을 넣는다.
2. **새 버전 만들기** → 앱 서명 안내가 나오면 **Google 에서 관리(Play 앱 서명)** 그대로 둔다 → 6단계 `app-release.aab` 업로드 → 출시 노트 `첫 버전` → 저장 → **출시 검토 → 출시**.
3. 왼쪽 메뉴 **앱 무결성 → 앱 서명** 에서 **앱 서명 키 인증서의 SHA-256 인증서 지문**을 복사한다.
4. Vercel 의 `ANDROID_CERT_SHA256` 을 `업로드키지문,앱서명키지문` 처럼 **쉼표로 두 개** 넣고 Redeploy 한다.
5. 내부 테스트 **테스터** 탭의 참여 링크를 폰에서 열어 참여 → Play 스토어에서 설치.

**확인** (폰에서)
- 위쪽에 **주소창이 안 보인다**. 보이면 4번 지문을 다시 확인하고, 앱을 지웠다 다시 설치한다.
- 로그인이 유지된다 · 알림 허용 후 설정 → 테스트 알림이 "마이리얼티" 이름으로 온다 · 지도·사진 첨부가 된다.
- 이 상태에서 화면 캡처를 4~6장 찍어 7단계 스크린샷에 올린다(개인 정보가 안 보이게).

## 9단계. 비공개 테스트 — 12명 × 14일

개인 계정은 이것을 마쳐야 정식 출시를 신청할 수 있다.

**할 일**
1. **테스트 → 비공개 테스트** → 트랙 관리 → **국가: 대한민국** 추가.
2. **테스터** 탭: 이메일 목록에 테스터 **12명 이상**(넉넉히 15명 권장)의 Gmail 을 넣는다.
3. **새 버전 만들기** → 8단계 버전을 **라이브러리에서 추가**(또는 같은 .aab 업로드) → 출시 검토 → 출시. 이번에는 **Google 심사**를 거친다(보통 1~3일).
4. 심사가 끝나면 **참여 링크**를 테스터들에게 보낸다. 각자 링크에서 "테스터 되기" → 설치.
5. **14일 동안 테스터가 앱을 지우지 않게** 부탁한다. 가끔 열어 보고 의견을 주면 더 좋다(정식 출시 신청서에 테스트 내용을 묻는다).

**확인**: 비공개 테스트 화면에 참여 테스터 수가 12 이상으로 보인다. 14일째 대시보드에 **프로덕션 액세스 신청**이 활성화된다.

## 10단계. 정식 출시

**할 일**
1. 대시보드 → **프로덕션 액세스 신청** → 설문 작성(테스트 기간에 받은 의견, 고친 점, 앱 소개). 승인까지 보통 7일 이내.
2. 승인되면 **테스트 및 출시 → 프로덕션 → 새 버전 만들기** → 비공개 테스트 버전을 라이브러리에서 추가 → 출시 검토 → 출시.
3. 심사(1~7일)가 끝나면 Play 스토어에서 `마이리얼티` 로 검색된다.

**끝나면**: Vercel 에서 `REVIEW_LOGIN_EMAIL`·`REVIEW_LOGIN_CODE` 를 지운다(나중에 업데이트 심사 때 다시 넣는다).

## 출시 후

| 바꾸는 것 | 할 일 |
|---|---|
| 화면·기능(대부분) | **웹만 배포**. 앱은 그대로 둬도 바로 반영된다 |
| 앱 아이콘·이름·웹 주소 | 코드 수정 → 6단계로 새 .aab → 프로덕션에 새 버전(버전 번호는 자동 증가) |
| 매년 여름(8월 말 전) | Google 이 요구하는 Android 버전(targetSdk)을 올려 새 .aab 를 낸다. Play Console 에 경고가 뜬다 |

## 막혔을 때

| 증상 | 해결 |
|---|---|
| 앱 위에 주소창이 보인다 | `assetlinks.json` 에 **앱 서명 키** 지문이 있는지(8단계 3~4). Redeploy 후 앱 삭제·재설치 |
| Actions Android 가 빨간색 | 4단계 비밀값 이름·내용 확인. base64 파일 내용을 **전부** 복사했는지 |
| 심사 거절 "로그인할 수 없음" | 5단계 심사 계정 값과 7단계 앱 액세스 설명이 같은지, 웹이 Redeploy 됐는지 |
| 심사 거절 "기능 부족·웹뷰" | 심사 계정에 관심 부동산·데이터가 있는지. 거절 사유를 알려 주면 대응 문구를 함께 쓴다 |
| 업로드 키를 잃어버림 | Play Console → 앱 무결성 → **업로드 키 재설정 요청**(Play 앱 서명이라 앱은 계속 업데이트 가능) |
