# 18. 부동산 유형별 지도 · 동네 시세 · 눈여겨볼 점

> 요청(2026-10): ① 지도 필터·레이어 설정이 저장되지 않고 계속 초기화된다, ② 지도에서 아파트 외 부동산을 고르면 상세가 없다,
> ③ 부동산 종류마다 관심사가 다르니 필터·레이어·지표·통계·인사이트를 유형에 맞게 바꾼다.

## 1. 확인한 사실(운영 DB, 2026-10-03, 최근 1년)

| 항목 | 값 | 의미 |
|---|---|---|
| 오피스텔 거래 | 매매 1,632 · 전세 3,147 · **월세 10,373** | 오피스텔은 월세 수익이 관심사인데 지도는 매매·전세만 보였다 |
| 단독·다가구 | 매매 612 · 전세 2,626 · **월세 12,334** · 다가구가 78% | 임대용 다가구가 대부분 |
| 토지 | **지분거래 37%**(2,399/6,542), 직거래 64% | 기획부동산식 지분 쪼개기가 시세를 왜곡 |
| 상가(집합) | 1층 ㎡당 765만 vs 2층 이상 317만 | 층이 가격을 가장 크게 가른다(2.4배) |
| 상가 법인 매수 | 29% | 투자·사업 목적 거래가 많다 |

| **법정동 코드 없는 거래** | 토지 **71%**, 상가 18%, 단독 5% | 지도·동네 시세에서 빠짐 → §5 |

공시지가(123건)·필지(19건) 자료는 아직 적어, 지표는 실거래에서 바로 계산되는 것만 썼다.

## 2. 설정 저장(①)

- 원인: 레이어·배경·유형·거래 종류·기간은 저장 코드가 없었고, 조건은 localStorage 를 **마운트 뒤** 읽어 저장 effect 가 먼저 돌면
  기본값으로 덮어썼다(개발 모드 이중 실행에서는 매번).
- 쿠키 `map_prefs` 에 저장하고 서버가 첫 화면부터 그 값으로 그린다(`lib/map-prefs.ts`). 뒤로 가기로 예전 화면 데이터가 다시 쓰여도
  브라우저 쿠키를 먼저 본다. 예전 localStorage 값은 한 번 옮긴다.
- **유형별로 따로 기억**: 거래 종류(`kindByType`)·조건(`filtersByType`)·정렬(`sortByType`)·레이어(`layersByType`).
  토지의 지목 조건이 상가에 섞이지 않고, 오피스텔은 월세·수익률 순을, 토지는 지적도·용도지역 레이어를 기억한다.

## 3. 유형별 지도(③)

| 유형 | 거래 종류 | 먼저 보이는 조건 | 추천 묶음 | 추천 레이어 | 라벨 |
|---|---|---|---|---|---|
| 아파트 | 매매·전세·월세 | 가격·평형·준공·세대수 | 신축·갭·국민평형·재건축 연한·입지 | 정비구역·역·학교 | 전용 평당가 |
| 오피스텔 | 매매·전세·월세 | 가격·**월세·임대수익률** | **수익률 5%+**, 원룸·소형 | 역·병원 | 월세는 보증금/월세 |
| 빌라 | 매매·전세·월세 | 가격·월세·**전세가율** | **깡통 위험(80%+)**, 신축 빌라, 노후(재개발) | 정비구역·역·학교 | 전용 평당가 |
| 단독·다가구 | 매매·전세·월세 | 가격·주택 유형·준공 | 다가구·단독·노후 | 정비구역·학교·공원 | **대지 평당가** |
| 토지 | 매매만 | **지목·용도지역·지분거래** | 대지·농지·관리지역(지분 제외), 지분 빼고 보기 | **지적도·용도지역·토지거래허가** | 토지 평당가 |
| 상가 | 매매만 | **건물 용도·집합/통건물·층** | 1층 상가, 통건물, 근린생활 | 역·용도지역 | 건물 평당가 |

- 새 지표(`/api/map/points`): **추정 임대수익률**(단지형, 최근 12개월 월세×12 ÷ (매매 − 월세 보증금), ㎡당 중위, 30% 상한),
  월세 중위, 대지 평당가(단독), 지분·법인·직거래 비율. 전세가율·수익률은 단지형만 — 단독은 매매가 건물 전체, 임대는 방 단위라 비교가 안 된다.
- 1년 변동은 읍면동 집계(토지·단독·상가)에서 각 기간 6건 이상일 때만(필지·건물이 제각각이라 2건이면 −80%·+180% 같은 잡음).
- 지분거래 30% 이상인 동네는 라벨에 `⚠지분 N%`.
- 성능: 지분 여부는 원천 JSON(`raw`)에만 있어 토지·상가에서만 읽는다(아파트 3년 조회가 120초 → 0.9초). 월세 행은 필요한 기간만.

## 4. 동네 시세 상세(②) · 눈여겨볼 점

- 단독·토지·상가 실거래는 지번 일부가 가려지고 건물명이 없어 단지로 묶을 수 없다 → **읍면동 + 세부 유형**(주택 유형·지목·건물 용도)을 상세 단위로.
- 지도 선택 카드: 거래 종류 → 세부 유형 칩 → 요약 → 단위가격 점 그래프 → 거래 목록, 상세·이야기·매물·관심 등록 버튼.
- `/regions/[법정동코드]?type=`: 유형 탭, 1년 요약, 세부 유형별 시세, 단위가격 추이, 용도지역별 시세, 위치, 거래 내역, 동네 이야기.
- **눈여겨볼 점**(`regionInsights`, 표본이 충분할 때만):
  - 토지·상가: 지분거래 비율과 ㎡당 배율(일반 거래 대비) — 기획부동산 경고, 도로 지목 비중, 농지 취득 요건
  - 단독: 대지 단가, 30년 넘은 주택 비율(노후도), 전월세 전환율(보증금 1억 → 월세 환산)
  - 상가: 1층 프리미엄(배율), 임대료 비공개 안내
  - 공통: 법인 매수 비율, 직거래 비율(시세 왜곡 경고), 매매 거래량 1년 변화

## 5. 법정동 코드 없는 거래 연결(ETL)

- 원인: 읍면동 목록(`regions`)이 코드를 주는 아파트 등 실거래에서만 만들어져, 아파트 없는 리(대곶면 대능리 등)의 토지 거래는 잇지 못했다.
- `transforms/regions.fill_regions`: 브이월드 행정경계(`LT_C_ADRI_INFO` 리, `LT_C_ADEMD_INFO` 읍면동)를 이름으로 찾아
  시군구 코드·전체 이름이 맞는 것의 **법정동 코드·경계·중심**을 저장하고 거래를 잇는다. 좌표 없던 읍면동(김포·광양 33곳)도 코드로 경계를 받아 채운다.
  실패는 `geocode_cache`(`boundary:` 접두)에 3일 기억. `geocode_pending`(매일·부동산별 수집)에서 돈다.
- 시험(읽기만): 코드 없는 상위 40개 동네 이름 **40/40 매칭**, 거래 52,895건.
